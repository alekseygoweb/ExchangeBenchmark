# ExchangeBenchmark

Замер задержки торговых операций на **Binance** и **OKX** (фьючерсы и спот),
по двум транспортам — REST API и WebSocket.

- `latency_test.py` — цикл «разместить лимитный ордер → отменить ордер»,
  считает задержку размещения, отмены и суммы (мс).
- `socket_test.py` — отдельный замер времени открытия WebSocket-сокета
  (DNS + TCP + TLS + upgrade) и логина OKX.

> ⚠️ **Скрипт работает на БОЕВЫХ счетах (PROD, РЕАЛЬНЫЕ ДЕНЬГИ).**
> Размещаются настоящие лимитные ордера и сразу отменяются. Они должны стоять
> далеко от рынка (non-marketable), чтобы не исполниться. Весь риск на вас.

## Установка

```bash
pip install -r requirements.txt
```

## Ключи API (.env)

Ключи **не хранятся в конфигах** и не коммитятся в git. Они берутся из
переменных окружения, которые удобно держать в файле `.env`.

1. Скопируйте образец и заполните своими боевыми ключами:

   ```bash
   cp .env.example .env
   ```

2. Заполните в `.env`:

   ```dotenv
   BINANCE_API_KEY=...
   BINANCE_API_SECRET=...

   OKX_API_KEY=...
   OKX_API_SECRET=...
   OKX_API_PASSPHRASE=...
   ```

`.env` подхватывается автоматически (через `python-dotenv`, а если пакет не
установлен — встроенным мини-парсером). Реальные переменные окружения имеют
приоритет над значениями из `.env`, так что в CI ключи можно передавать
напрямую через окружение, не создавая файл.

Для Binance можно задать отдельные ключи под фьючерсы и спот
(`BINANCE_FUTURES_API_KEY` / `BINANCE_SPOT_API_KEY` и соответствующие секреты) —
они переопределяют общий `BINANCE_API_KEY`.

## Запуск

```bash
python latency_test.py        # спросит подтверждение (реальные деньги)
python latency_test.py --yes  # без подтверждения (например, для автоматизации)
python socket_test.py
```

**Рекомендуемый первый боевой прогон** — один рынок, один цикл, авто-цена и
авто-размер, чтобы убедиться, что ордер именно отменяется, а не исполняется:

```bash
python latency_test.py --exchange binance --market spot \
                       --repeats 1 --auto-price --auto-size
```

### Флаги командной строки

| Флаг | Назначение |
|---|---|
| `--exchange both\|binance\|okx` | Какую биржу гонять (по умолчанию обе). `binance` = «OKX закомментировать» |
| `--market both\|spot\|futures` | Какой рынок (по умолчанию оба) |
| `--repeats N` | Число повторов цикла (перекрывает `LATENCY_REPEATS`) |
| `--auto-price` | Авто-цена от рынка (см. ниже) |
| `--auto-size` | Авто-размер: минимальный валидный объём (см. ниже) |
| `--conditional` | Условный (trigger) бенчмарк Binance — отдельный конфиг (см. ниже) |
| `--no-balance-guard` | Отключить проверку баланса перед условным ордером (не рекомендуется) |
| `--skip-time-check` | Не сверять локальные часы с временем биржи |
| `--yes` / `-y` | Не спрашивать подтверждение |

## Конфиги (без секретов)

Торговые параметры лежат в `config_binance_PROD.json` и `config_okx_PROD.json`
(символ, сторона, цена, объём, URL-ы). Путь можно переопределить переменными
`CONFIG_BINANCE` / `CONFIG_OKX`.

### ⚠️ Важно про цену ордера

Биржи отклоняют лимитные ордера, стоящие слишком далеко от текущей цены
(price-band фильтры: Binance `PERCENT_PRICE_BY_SIDE`, OKX лимит цены). Заглушка
`"price": "20000"` для BTC на боевом рынке, скорее всего, будет **отклонена**.

Есть два варианта:

1. **Авто-цена (рекомендуется)** — пусть скрипт сам посчитает безопасную цену
   от текущего рынка (см. ниже). Тогда поле `price` в конфиге не используется.
2. **Вручную** — выставьте в конфигах цену в допустимом коридоре, но заведомо
   неисполняемую (например, BUY на несколько процентов ниже лучшего бида).

В любом случае проверьте, что объём проходит минимальный номинал биржи.

### Авто-цена (опционально)

Скрипт может сам подобрать **безопасную неисполняемую** цену: берёт текущие
лучшие бид/аск, отступает на `PRICE_OFFSET` процентов в «безопасную» сторону
(для BUY — ниже бида, для SELL — выше аска) и округляет к шагу цены инструмента
(`tickSize`). Цена заведомо не пересекает спред (ордер не исполнится) и при этом
попадает в ценовой коридор биржи. Запросы цены делаются **до** таймера и на
замер задержки не влияют.

Включение (любой из способов):

```bash
python latency_test.py --auto-price --yes          # флаг командной строки
AUTO_PRICE=1 python latency_test.py --yes           # переменная окружения
```

или в конфиге (общий ключ или внутри блока рынка):

```json
{ "auto_price": true, "price_offset_pct": 1.0, "futures": { ... } }
```

Отступ задаётся через `PRICE_OFFSET` (проценты, по умолчанию `1.0`) или
`price_offset_pct` в конфиге. Перед таблицей печатается посчитанная цена:

```
  [auto-price] Binance futures: 99000.0
  [auto-price] OKX spot: 99123.4
```

### Авто-размер (опционально)

Чтобы не подбирать объём вручную и не словить reject по `LOT_SIZE` /
`MIN_NOTIONAL`, скрипт может взять с биржи минимальный валидный размер:

- **Binance** — из `exchangeInfo`: `LOT_SIZE` (`minQty`/`stepSize`) и
  `MIN_NOTIONAL`/`NOTIONAL`. Берётся наименьший объём, кратный шагу, чей номинал
  ≥ минимального.
- **OKX** — из `public/instruments`: `minSz`/`lotSz`. Для **SWAP размер в
  КОНТРАКТАХ** (1 контракт = `ctVal` базовой валюты), не в BTC.

Включение: `--auto-size`, или `AUTO_SIZE=1`, или `"auto_size": true` в конфиге.
Посчитанный размер печатается строкой `[auto-size] ...`. Рекомендуется вместе с
`--auto-price`, чтобы номинал считался от реальной цены.

### Зачистка после прогона (reconcile)

Каждый цикл размещает и тут же отменяет ордер, но на путях ошибок (reject,
частичное исполнение, таймаут отправки — когда ответ не дошёл, а ордер мог
создаться) могут остаться «висячие» ордера. Поэтому после каждого рынка скрипт
делает **reconcile**: снимает свои незакрытые ордера (только с префиксом
`clientOrderId`/`clOrdId` = `lt…`, чужие ордера не трогаются) и проверяет
позицию. Итог печатается строкой:

```
  [reconcile] Binance spot: ок (снято наших=0, осталось=0, позиция=0)
  [reconcile] OKX futures: ⚠ снято наших=1, осталось=0, позиция=0.1 — ПРОВЕРЬТЕ ВРУЧНУЮ!
```

Позиция `≠ 0` означает, что какой-то ордер всё же исполнился — её скрипт
**не закрывает сам** (это была бы новая сделка), а громко предупреждает.

### Режим позиции на фьючерсах (hedge / one-way)

Binance Futures в режиме хеджирования (dual-side) требует `positionSide`
(LONG/SHORT) в каждом ордере — иначе `-4061 Order's position side does not
match`. Скрипт определяет режим счёта автоматически (`GET
/fapi/v1/positionSide/dual`) и в hedge-режиме ставит `positionSide` из стороны
ордера (BUY→LONG, SELL→SHORT); в one-way режиме поле не добавляется. При желании
можно задать `position_side` в конфиге явно. В начале фьючерсного прогона видно:

```
  [pos-mode] Binance futures: hedge → positionSide=LONG
```

### Условный (trigger) бенчмарк

На многих биржах условные/algo-ордера идут через **отдельную подсистему** с
другой задержкой, чем обычный LIMIT. Если вы торгуете триггерными ордерами —
этот путь полезно мерить отдельно. Включается флагом `--conditional` и
использует **отдельный конфиг** `config_binance_PROD_conditional.json`
(обычный прогон по умолчанию остаётся безопасным лимитным).

```bash
python latency_test.py --conditional --exchange binance --market futures --repeats 1
```

По умолчанию там стоит `STOP_MARKET` (BUY), `quantity: 100`, `stop_price: 1000000`,
`working_type: MARK_PRICE` — триггер срабатывает только при росте цены до
1 000 000, то есть **никогда**. Ордер размещается как несработавший, **не
резервирует маржу до срабатывания** (работает на пустом фьючерсном кошельке) и
сразу отменяется. В hedge-режиме `STOP_MARKET` — это корректный *открывающий*
условный ордер для LONG; `TAKE_PROFIT_MARKET` в hedge даёт `-4120`.

Важно понимать про размер: **задержка `place`/`cancel` не зависит от объёма** —
матчинг-движок одинаково быстро принимает и `0.002`, и `100` BTC для
несрабатывающего ордера. То есть `100` BTC не даёт замеру ничего сверх
минимального размера; крупное число здесь не «точность», а только риск.

**Balance-guard.** Главная (и единственная реальная) опасность такой схемы — она
безопасна, только пока счёт пустой; после пополнения «100 BTC / триггер 1000»
превращается в заряженную пушку. Поэтому перед условным ордером скрипт проверяет
свободный баланс и **отказывается запускаться**, если доступно больше
`MAX_EQUITY_USDT` (по умолчанию 50 USDT):

```
  [balance-guard] Binance futures: доступно 12.50 USDT ≤ 50 — ок
  ...
  balance-guard: доступно 5000.00 USDT > порога 50. Условный ордер 100 BTCUSDT ... 
```

Отключается через `--no-balance-guard` / `BALANCE_GUARD=0` (не рекомендуется).
Условный бенчмарк рассчитан на **фьючерсы** (на споте 100 BTC резервирует
средства при размещении и отклоняется по балансу).

### Проверка времени биржи (offset)

Перед прогоном скрипт сверяет локальные часы с временем биржи
(`GET /fapi/v1/time`, OKX `/api/v5/public/time`): кривое время и портит замер, и
вызывает reject по `recvWindow`. Печатает offset; при `> 500 мс` — предупреждение,
при `> 3000 мс` — **останавливается** (можно обойти `--skip-time-check`):

```
  [time] binance: offset +7 мс — ок
```

### Синхронизация времени (NTP)

Биржи отклоняют запросы при рассинхроне часов (`Timestamp ... recvWindow`), а для
замера задержки кривое время вообще обесценивает результат. На Linux:

```bash
timedatectl                 # нужно 'System clock synchronized: yes', 'NTP service: active'
sudo timedatectl set-ntp true
```

Для более точной синхронизации — `chrony`:

```bash
sudo apt install chrony
sudo systemctl enable --now chrony
chronyc tracking            # 'Last offset' / 'RMS offset' должны быть в миллисекундах
```

### Чек-лист перед первым боевым запуском

1. Ключи с правом **Trade**, **без Withdraw**, привязаны к IP.
2. Часы синхронизированы (NTP, см. выше).
3. Цена внутри коридора (`--auto-price`), направление BUY-ниже / SELL-выше.
4. Размер минимальный и валидный (`--auto-size`).
5. Первый прогон — **один рынок, один цикл** (`--exchange binance --market spot --repeats 1`).
6. После — посмотреть строки `[reconcile]`, убедиться что позиция `0`.

## Переменные окружения (сводка)

| Переменная | Назначение |
|---|---|
| `BINANCE_API_KEY`, `BINANCE_API_SECRET` | Ключи Binance (общие для спота/фьючерсов) |
| `BINANCE_FUTURES_*`, `BINANCE_SPOT_*` | Необязательные ключи под конкретный рынок |
| `OKX_API_KEY`, `OKX_API_SECRET`, `OKX_API_PASSPHRASE` | Ключи OKX |
| `CONFIG_BINANCE`, `CONFIG_OKX` | Пути к конфигам |
| `LATENCY_REPEATS` | Число повторов цикла (по умолчанию 5) |
| `LATENCY_CONFIRM` | `1`/`yes` — пропустить подтверждение |
| `AUTO_PRICE` | `1`/`yes` — авто-цена от рынка (= флаг `--auto-price`) |
| `PRICE_OFFSET` | Отступ авто-цены от бида/аска в процентах (по умолчанию 1.0) |
| `AUTO_SIZE` | `1`/`yes` — авто-размер: минимальный валидный объём (= флаг `--auto-size`) |
| `CONDITIONAL` | `1`/`yes` — условный (trigger) бенчмарк (= флаг `--conditional`) |
| `CONFIG_BINANCE_CONDITIONAL` | Путь к условному конфигу (по умолчанию `config_binance_PROD_conditional.json`) |
| `BALANCE_GUARD` | `0`/`no` — отключить balance-guard (по умолчанию включён) |
| `MAX_EQUITY_USDT` | Порог balance-guard в USDT (по умолчанию 50) |
| `SKIP_TIME_CHECK` | `1`/`yes` — не сверять часы с биржей |
